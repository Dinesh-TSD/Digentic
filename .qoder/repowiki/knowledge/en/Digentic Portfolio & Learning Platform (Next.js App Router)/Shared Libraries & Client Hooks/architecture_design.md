Flat module layout under `lib/` and `hooks/` that is imported by both server and client code. Database access is split into two parallel connectors: `mongodb.ts` exposes the native `MongoClient` with a process-scoped promise (cached via `global._mongoClientPromise` in development) and an exported `getDatabase()` helper; `mongoose.ts` wraps Mongoose with its own global `mongooseCache` to reuse a single connection per process. Email delivery lives in `email.ts`, which conditionally uses Nodemailer when SMTP env vars are present and falls back to console logging for local dev. Data layer files (`constants.ts`, `courses-data.ts`, `digital-products.ts`) export typed static datasets — `constants.ts` holds site config, navigation, footer links, and mock content; `courses-data.ts` defines `Course`/`Lesson`/`Section`/`Review` interfaces plus a large `COURSES` array generated with a `makeLessons` helper; `digital-products.ts` defines `DigitalProduct` type and a `DIGITAL_PRODUCTS` array with category/badge metadata. `utils.ts` re-exports a `cn` class-name combiner built on `clsx` + `tailwind-merge`. The `hooks/use-toast.ts` file is a self-contained client-only (`'use client'`) state machine implementing a reducer-driven toast system with ADD/UPDATE/DISMISS/REMOVE actions, a listener registry, and a `useToast` hook that mirrors `react-hot-toast`-style API.
